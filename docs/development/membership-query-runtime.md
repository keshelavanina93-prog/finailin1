# Typed membership over retained source objects

Property filters accept `in` and `not_in` with a required array of 1–100 non-null typed scalar candidates. Both operators exclude absent, null and schema-incompatible historical fields. Equality follows exact stored values; membership does not infer currency, normalize business identifiers or assign financial meaning. Root and per-hop membership candidates share the query's global bound of 100. Existing scalar filter payloads retain their prior behavior.

The authentic proof scopes CompanyDimensions to SourceEvidence `71f45f39-35fb-56c1-b4b7-61e7edc56368`. The actual source columns are `Y` (Region), `AA` (Department), and `Z` (Budget Article New). `source_column in [Y, AA]` selects the exact Region and Department contexts; `not_in [Z]` under the same evidence scope returns those same two. These are source-classification selections, not counts of financial accounts or transactions.

`scripts/verify-membership-query-runtime.py` separates normal canonical definition review (`--prepare`) from execution and retained replay. The stable governed key is `sog-source-contexts:membership:v1`. Preparation creates a saved ObjectSet and a pure observation Function without introducing business identities. Runtime invokes the compiled shared ontology SDK using an absolute D-drive Node executable and D-drive working directory. The SDK checks the exact saved-set version, frozen timestamps, membership filters, two one-row pages, return to the first page, and null at the end. A typed outgoing `source_record_id` traversal uses evidence membership at the destination and verifies original source-record identities. No interface mapping is invented for this proof.

The Function result must preserve the SDK's exact source objects and filters, and retained replay must preserve the complete invocation.
