# Regulatory source-to-assessment execution

NIN-26/NIN-6 ontology prerequisite for NIN-40, implemented 2026-09-06. This advances actual regulatory behavior beyond registry editors; it does not complete regulatory monitoring or compliance delivery.

The Regulation workspace now fetches an exact Matsne document/publication from the official HTTPS endpoint. Fetch is bounded, requires existing intake permission, rejects redirects/errors and rejects a response serving a different document/publication. Original bytes are retained in the existing evidence store. The ontology stores compact `SourceRegulatoryPublication` metadata/hashes and references to the original document and canonical `RegulatoryAct`; legal text remains in evidence storage. Source-bound validation reparses the retained original before publication and review.

The parser records served/advertised publication numbers, original registration/adoption/publication metadata and legal text hash. Older publications, restricted consolidation, missing annex retention and unverified completeness stay explicit. No parser output claims verified current law. A Matsne rule cannot assert complete applicable source law unless its referenced publication supports that assertion; the current capture path intentionally does not supply such verification.

Reviewed publication history and retained-source readback are usable in Regulation. Exact-version comparisons require the same canonical act, re-read retained original text and verify text hashes, and persist a document-text diff through the existing calculation authority. Differences do not activate legal or financial changes.

Company assessments now collect the full authorized rule scan at fixed legal/knowledge times rather than treating a paginated response as the whole assessment. Retained results include company/version, scenario inputs, rule/dependency versions and all unresolved gates. A source-completeness issue no longer hides missing customer context or licence binding. Reopening preserves the recorded company and time context. An empty rule set is explicitly not a compliance pass.

## Durable source monitoring

Regulatory Sources now creates persistent Temporal Schedules through the existing worker and platform workflow request/event authority. Each action is a bounded source-check workflow with three activity attempts and exponential backoff; overlap is skipped and catch-up is bounded. Configuration, actor/scope and request identity are retained. Retries reuse successful check checkpoints. Failed attempts keep previous evidence and expose failure; current execution state is checked separately so a revoked worker grant cannot leave the UI falsely healthy. Pausing stops future scheduled actions, not an already running capture.

Checks retain original bytes and compare legal text hashes, advertised publication sets and completeness. They do not approve interpretations or activate accounting. The UI exposes the schedule, last success, last new observation, next check, overdue status, controls and evidence readback. Source-publisher latency remains unknown. This connector checks an explicit Matsne publication and discovers advertised revision numbers; it does not automatically acquire every amendment or annex, or cover GNERC feeds and other publishers.

## Source-to-ontology impact continuation

Source inspection can now execute and reopen a retained dependency-impact trace. The implementation factors the existing proposal dependency traversal into a shared engine with a read-only accepted-root entrypoint; it does not manufacture a proposal or create a second intelligence graph. It preserves the existing bounded traversal, hidden-consumer refusal and cycle safeguards. A repeatable-read transaction pins the act, downstream accepted heads and exact rule field references to one database snapshot. The existing content-addressed run authority retains the result and rechecks referenced version access on reopening.

Authentic browser trace `fcr_577e02e764e99d318eeffb303d451c91aef0ff8c92f95f9bef6b1999008d1f61` connects the monitored Matsne accounting publication to its accepted act, SourceRegulatoryPublication, SGG interpretation, and original company/licence/evidence version bindings. The operator can execute this from the monitor's retained evidence and reopen the same trace. Financial impact is explicitly UNAVAILABLE with amount null; dependency reachability is not a claim of legal applicability or quantified loss/profit impact. Only registered accepted dependencies are covered; missing bindings do not establish no business impact.

Build and lint passed. Canonical Finding/Investigation lifecycle and executable financial propagation remain downstream work, not completed by this trace.
