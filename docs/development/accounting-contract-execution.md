# Accounting contract execution for SGP and SGG

Shared FactContract execution now supports additive flows, exact-date closing balances, exact-date cumulative snapshots, non-additive values and ratios recalculated from summed components. Ratios retain numerator/denominator and explicit HALF_EVEN rounding; zero denominators remain unavailable. Existing contracts retain their semantics. Cumulative values are not converted to monthly movements without a separate approved transformation.

Contracts may declare mandatory accounting partition fields (company, ledger, scenario, balance side, tax/valuation/translation/reporting basis as appropriate). These must belong to the grain and remain in grouping even when omitted by the caller. This mechanism preserves declared distinctions; it does not infer or certify an undeclared accounting basis, determine VAT recoverability, cost inventory or translate currencies.

Source family and duplicate-grain checks remain enforced. Explicit row-role selection rejects other source roles. Optional hierarchy identities reject directly linked parent and child rows selected together within a period/unit/accounting scope; neither parents nor leaves are universally designated authoritative. Missing hierarchy relationships are not inferred.

FactReconciliation is a reviewed canonical definition that pins two FactContract versions. The runtime aggregates each side separately, then compares compatible dimensional coordinates, including period, mandatory partitions and currency/unit. It returns differences and missing sides without turning absence into zero or adding GL/TB/sales representations together. An explicitly designated authority side is retained; matching is not financial certification. Ratios must be reconciled through their components. Changed contract dependencies block execution pending review. Both queries use one effective/knowledge timestamp.

API: POST /v1/ontology/model/facts/{id}/aggregate and /reconcile. The Ontology workspace now exposes Accounting Facts & Reconciliation with reviewed contract selection, grouping, exact source-date selection, results and input versions. The date picker uses exact stored date equality; timestamp-grain and interval queries require the API's explicit Object Set scope. This interface does not establish complete period coverage.

The FactReconciliation schema was installed through existing independent publication proposal a1a60910-7790-43e7-a88c-7ba60444b78e. Focused checks cover cumulative snapshots, component ratios, accounting partitions, row roles, direct hierarchy overlap and reconciliation missingness; lint/TypeScript/production build passed. This is implementation evidence, not complete SGP/SGG financial-report acceptance. No financial facts were seeded to make the screen appear populated.

Still required: authentic SGP/SGG company/chart/fact bindings; source completeness and period coverage; reconciliation review/disposition workflows; tax recoverability and signed gross/net treatment; inventory valuation and recognition timing; currency roles and approved rate-type/version execution; taxonomy adjustments and full financial/regulatory reporting integration. Generic grouping safety must not be reported as completion of these policies.

Calculation API responses are now retained in append-only fact_calculation_runs (migration 025), keyed by the canonical result hash including exact scope and runtime version. GET /v1/ontology/model/fact-runs/{run_id} verifies content integrity and current access to referenced versions. The workspace can reopen a retained reference without recalculating current sources. Storage, duplicate-write idempotency and authorized reopening were exercised in a rolled-back database transaction, leaving no synthetic financial run in the workspace. Retention does not mark a discrepancy resolved or certify its authority.
