# Executable type groups over original canonical objects

NIN-6 type groups now form exact, reusable Object Set roots. Opening a group previously returned a collection using a literal interface query type; subsequent editing, saving and downstream consumption could lose the group contract. The reviewed group now runs through the same query compiler, saved definitions, deterministic Functions, retained inputs and G8 Ontology workbench as other roots.

`ObjectSetQuery.type_group` contains an exact resource/version pair, requires `object_type: ObjectTypeGroup`, and excludes an interface root. The group retains one exact `DEFINITION_TYPE` schema dependency for each of its one to one hundred unique concrete types. Its common properties are the intersection of complete field specifications, excluding only the per-schema field identity. Requiredness, semantic identity, reference target and field policy cannot be weakened to manufacture a common property.

Shared filters execute before the global count and page. The existing typed compiler follows common reference fields and subsequent relationship steps. Publication and runtime reuse the same exact-definition resolver. Original objects and identities remain unchanged. `type_group_bindings` carries the group, member schema pins/hashes and common fields; separate `type_group_values` reports each original member's schema compatibility. An unfiltered incompatible member reports `SCHEMA_CHANGED`. Filtering or traversing such a root fails explicitly with 409. Traversed endpoints do not acquire invented group membership.

Static exact definition versions may postdate the data cutoff. They do not advance valid/known data time. The workbench retains the exact group, source roots, predicates, traversal and timestamps when saving, paging or returning. Functions retain group metadata alongside the same query and original objects. Existing review, access, temporal and accounting boundaries still apply. No migration or additional identity store was introduced.
