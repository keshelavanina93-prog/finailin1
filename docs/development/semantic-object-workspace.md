# Canonical definition workspace

NIN-60 extends the shared analysis read contract to canonical objects without an
approved analytical measure. The named consumer is the existing SEG LocalAccount
set, attributed through its exact LocalChartOfAccounts version to the canonical
company. The same renderer can inspect other supported canonical definitions;
there is no account-specific renderer, new object identity or copied registry.

`semantic-analysis/2` adds explicit `measure: null`, `visual: NONE`,
`row_noun: objects` and an `ATTRIBUTE` field role. Stored numeric attributes are
not promoted to measures. Existing `semantic-analysis/1` responses keep their
serialized shape and retained result references. Filtering selects exact typed
values from the original result, and arrangement partitions rows without sums.
No joins, forecasts, financial report completeness or business effects are granted.

The compiler reads the original shared Function invocation, checks its exact
Function, plan, result, object type/schema/version and semantic dependencies, then
returns existing object/version pins as the grain and trace references. Supported
company attribution is the direct legal entity reference or the existing typed
chart, ledger and book ownership paths. Mixed schemas, mixed company revisions,
unknown ownership and altered retained objects are refused. Query-page coverage
and further pages remain explicit; 38 accounts do not prove the complete chart.

Bound source definitions supply their own SourceRecord and SourceEvidence pins.
An account's separate transaction-use evidence cannot substitute for its chart
definition source. Original cells can be read from existing source documents or
existing construction receipts, always through the current exact access scope
and verified file hash. The construction path uses the existing bounded workbook
reader and preserves formula expressions and cached values without execution.
`Contributor.basis` distinguishes original source, canonical definition fallback,
and unavailable original source. Canonical attributes are never labelled original
workbook values.

The preparation helper defaults to a read-only inventory. Its explicit `--apply`
path uses the existing reviewed ObjectSet/Function lifecycle and ordinary operator
execution. It creates no accounts, companies, schema or accounting interpretation.
Function invocation identity is version- and actor-keyed; retry reopens the original
receipt. The native HTTP verifier is read-only. All runtime and evidence files stay
on D:.

Focused builder verification covers provenance, typed missing/null/zero values,
company/schema/version mismatches, unavailable evidence, partial pages, and original
construction cells including formulas and tampered hashes. These checks do not
establish full ontology, intelligence, financial-report or release acceptance.
Product browser and independent unfamiliar-shape acceptance require their own
frozen integrated evidence.
