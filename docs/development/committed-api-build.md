# API build from verified committed source

`scripts/build-api-artifact.py --archive <source.zip> --python <D-local-python.exe>` verifies a source archive whose commit belongs to the current repository history, prepares a fresh directory, and builds the API wheel with dependency downloads disabled. It checks the installed build-tool versions against the archived Windows lock and records the Python target, input hashes, builder/verifier hashes and wheel SHA-256. Build subprocesses receive a minimal environment without application credentials. This is not a network sandbox.

The source inventory and every file hash must remain unchanged after building. The wheel must contain exactly the archived package files, all canonical SQL migrations, and the expected metadata files. Package bytes, migration bytes, distribution identity, Python requirement, wheel tag and RECORD hashes are checked. Dependency metadata equivalence remains explicitly unverified; this is not a complete dependency/SBOM attestation.

Actual committed-source proof uses commit `7c26eebc2681b04d97d9da06744cf5079a483185`, source archive `135531cd50aae31df4449ab99cc463c705c6362c27d3ebe114863385016bd15a`, and wheel `ad02f3d51be927f56705a90143b6171bc19fff85c277f9f5e334f2bc277ee41a`. The final build receipt is retained under `.finai/artifacts/api-builds/build-ka2ujr8a/`. Nine focused checks passed, including source mutation, unexpected wheel contents, metadata/RECORD mismatch and environment isolation.

That exact wheel was installed into the isolated D-local validation environment. Imports resolved from site-packages, all dependencies passed pip check, and the installed readiness function returned ready for the database, schema and evidence store. This was a direct readiness check, not an HTTP server deployment, worker execution or release acceptance. Its Function dependency hash differs from the active dirty checkout as expected; it must not reuse that checkout's accepted execution pins.

The first frontend build from the same committed archive compiled successfully, but artifact collection refused its nested server layout: Next inferred the outer checkout as the tracing root. The configuration now explicitly binds tracing and Turbopack to the materialized monorepo root. A new committed-source frontend build is required to verify that correction.
