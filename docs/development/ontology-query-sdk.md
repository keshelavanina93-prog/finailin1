# Shared executable ontology query SDK

NIN-6 now provides `@g8/ontology-client`, consumed by the G8 Object Sets workbench and a native Node application. Applications use one query client for concrete objects, exact saved sets, interfaces and type groups. The client uses the existing authenticated ontology endpoints and creates no registry, resource identities, query engine or business effects.

`createOntologyClient({baseUrl, getToken, fetch?})` exposes `query`, `runSavedSet`, `runGroup`, `page` and `nextPage`. Saved definitions require an exact resource/version pair. Paging posts the previous returned query with its original valid/known timestamps, source roots, predicates, relationship steps and interface/group pins. Definition references survive paging. End-of-results returns null without another request. The client captures inputs before asynchronous authentication, forwards cancellation, refreshes authentication per request and performs no automatic retries or redirects.

Requests and responses are checked against JSON schemas generated from the canonical Python query and public API response models. `scripts/generate-ontology-query-contracts.py` emits `packages/contracts/src/ontology-wire.ts`: portable wire types, three JSON schemas, contract version and schema hash. `--check` refuses drift. Unsupported schema constructs fail generation rather than silently weakening the generated type. Dynamic business attributes retain their canonical schema authority. The response envelope validates original resource identities, exact bindings and compatibility metadata; additional original provenance and written timestamp precision survive serialization unchanged.

The SDK additionally checks response contract version, exact definition/root bindings, unchanged query scope, microsecond-preserving timestamp equivalence, safe integer filter values, counts, pagination and compatibility against each original object. Frozen pages reject changed schema bindings or populations. HTTP refusal status remains available through `OntologyClientError`; non-JSON/malformed success is an error, never an empty dataset. This checks transport consistency, not independent attestation of the server or financial authority.

Two Python checks prove the retained interface/group payloads preserve original object/provenance fields and reject missing definition versions or invalid object versions. Generated-contract drift checking, scoped Python lint/typing, shared contract and client builds, frontend lint/typing and the application production build passed.

For both retained 1C/SOG interface and type-group sets it proved exact saved execution, pages of one, return to the first page, null at the end, unchanged objects, evidence filtering, source-record traversal and exact provenance hashes.
