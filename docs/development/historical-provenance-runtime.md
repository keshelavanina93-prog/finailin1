# Historical provenance and active source-reference review

Evidence analysis can retain historical calculated provenance while active references still require current eligible versions. This distinction does not relax strict authoritative consumption or certification. A retained historical dependency is not a substitute for reviewing a stale active `FIELD:dimension_id` reference.

The authentic proof revisits the Region and Department CompanyDimensions used by the original blocked parallel build. Their source facts are unchanged, but their active references still point to target versions preceding independently reviewed display updates. The source review preserves both canonical identities, identity keys, display names, every attribute, evidence classification and access boundary. Normal canonical review records new source versions whose active references bind the already reviewed target versions. It does not invent new business identities or rewrite the historical source versions.

`scripts/verify-historical-provenance-runtime.py` separates pending source-proposal preparation, explicit independent approval, and subsequent build preparation. The pending proposal is retained before approval so the browser can inspect the concrete unchanged values and reference-version update. Target attributes and exact current target versions are checked against the preceding display-binding proof. The original blocked preparation remains preserved separately.

After approval and runtime freeze, the helper republishes the original v1 Region/Department ObjectSets, Functions and three-node Transformation under their existing governed identities. It checks evidence-catalog availability, actual build outputs, unchanged source facts, the exact retained Region input, readable older receipts and continued refusal of stale ACTIVE source references even with evidence-only historical traversal enabled.

## Focused validation and limits

Four historical-provenance cases and one existing Function regression case passed, along with targeted Ruff/mypy, frontend lint/TypeScript and the production build. This establishes the bounded evidence-analysis and reviewed-reference continuity contract. Strict consumption, certification, financial authority and production/product/release acceptance remain outside this proof. Completed-result restart readback does not establish arbitrary mid-execution recovery.

Preparation retries reuse the exact saved proposal and timestamps rather than creating another proposal. Historical receipt readback selects the existing grant of the original retained invocation actor; sharing an exact scope does not imply identical read visibility. No grants or scopes are changed. Browser build adoption reads the original compiled request through `--request-id`.
