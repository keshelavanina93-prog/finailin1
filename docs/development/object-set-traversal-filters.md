# Typed filtering through the shared object graph

NIN-6 Object Sets can now filter the canonical objects reached at each relationship step. Previously, predicates applied only to starting objects; an analyst could follow a source dimension to observations but could not constrain those reached observations by date before following another relationship. The same query is reusable by the browser, saved ObjectSetDefinition, derived-property evaluation, source binding and shared Function runtime.

`Traversal.filters` is optional and omitted when empty, preserving existing definition serialization. Queries support four relationship steps and twenty total predicates across roots and steps. Each stage applies its predicates before the next traversal and before final deduplication, counts and pagination. Comparisons reuse canonical scalar types, including exact decimal text and timezone-aware timestamps. The destination type contract is checked even when the starting set is empty.

Outgoing relationships retain their exact referenced resource versions. Query-time schemas and each reached object's retained schema must agree on the filtered property definition. An incompatible or unavailable reached schema produces an explicit refusal naming the stage, rather than an apparent zero-match result. Metadata resolution for filtered traversal runs under the shared canonical publication lock; the counts, page and incompatible-stage checks share one SQL statement. Caller values remain parameters. Existing tenant and visibility rules remain in force.

Results retain `traversal_schema_versions`, with a one-based step and the exact schema resource/version for every filtered destination type. Root `filter_schema_versions` remains separate. Function results and downstream retained-input consumption preserve these pins with the query and contributor versions. Endpoint results are distinct object versions; the result does not claim a separate receipt for every intermediate path.

Incoming-reference discovery now separates inspected candidate schemas from actual dependencies. Discovery retains its temporal resolution, visibility rules and publication head checks; matching endpoint schemas are then bound and checked through the normal definition dependency path. An unrelated revoked schema cannot contaminate a saved query's upstream authority. Actual dependency withdrawal checks remain in force.

The Object Sets workbench now preserves all steps and explicit root identities when opening, editing, saving and replaying a query. It provides repeatable relationship steps and typed reached-object filters, shows applied comparisons and schema pins, and keeps null equality explicit. A selected root set is cleared only by an explicit action or root-type change. Ambiguous or wildcard endpoints cannot silently acquire guessed filter semantics.

Authentic proof uses the retained SOG-Kartli dimension: incoming member assignments restricted to source evidence `71f45f39-35fb-56c1-b4b7-61e7edc56368`, then outgoing observations with posting dates from 2025-11-03 inclusive to 2025-11-04 exclusive. These are source-observed dates; the valid/known query snapshot remains explicit and distinct. The exact results are the source movements at TR!5 and TR!6. A third relationship step reaches their one shared debit account without duplicating it. No journal, currency, reporting or financial authority is inferred.

`scripts/verify-object-set-traversal-runtime.py` prepares reviewed reusable definitions, runs the packaged HTTP path and compares exact source evidence, Function output and retained-input output. Its replay/read-only modes verify retained receipts across runtime restart. Concrete results are recorded in `evidence/nin6-object-set-traversal-runtime.json`; focused verification and browser evidence accompany that artifact. This advances the shared ontology runtime under the current NIN-44 order; full NIN-6 and product acceptance remain open.
