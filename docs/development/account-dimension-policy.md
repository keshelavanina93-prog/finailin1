# Reviewed account analytical requirements

NIN-17 now uses the existing canonical AccountDimensionRule authority to declare the complete allowed analytical dimensions for a LocalAccount. AccountDimensionPolicy retains exact rule versions under one deterministic account identity, together with the account, chart and company. An explicitly empty rule set requires the same proposal and independent review as a nonempty set. An absent policy is unestablished.

Rule discovery uses current effective versions. A future-effective editing head does not hide the still-effective rule. Migration 054 provides a boolean completeness witness under the existing policy-reader role: a visibility-filtered list cannot silently become an empty or partial accepted policy. The helper verifies the complete effective rule version set, account dependency and entity boundary without returning hidden identities. Application validation separately checks availability, exact relationships and review authority. This helper is not a new journal publication database trigger.

New JournalLine proposals require `journal-line-dimensions/1`, an exact reviewed policy, and explicit member assignments (possibly empty). Validation rejects missing required dimensions, duplicates, dimensions outside the policy and stale exact pins. Rules, policies and journals are reviewed separately. Policy and rule dependencies can resolve their exact current-effective version while retaining the editing-head concurrency fence. Other accounting and source dependencies retain their existing checks.

An assignment is either USER_ASSERTED with a reason or REVIEWED_SOURCE_ATTRIBUTION with a reason, exact source-assignment version and explicit debit/credit side. Source attribution validates the retained assignment, member, company dimension, movement, corresponding account side, source row and common evidence. Source-row analytics are not automatically attributed to both journal sides. No account-code prefix or file name creates accounting meaning.

Historical readback resolves retained policy, rule, member and source relationships. It does not apply today's complete rule set to an older journal. A pre-policy line remains UNESTABLISHED; mathematical journal balance remains a separate result. Missing retained analytical dependencies prevent a complete analytical readback without manufacturing assignments.

The business shell opens the same analytical-policy workbench from a selected canonical account in NYX context and from an explicitly chosen source account-definition candidate. It presents all existing rules, required/optional status, exact context, a review reason and a retained proposal receipt. Source candidates remain candidates. Governed change review includes the policy, and the company journal explorer exposes each line's analytical state and provenance separately from debit/credit totals.

The API uses GET `/v1/ontology/account-dimension-policy` and POST `/v1/ontology/account-dimension-policy/proposal`. It requires exact company/chart/account references, preserves the account access boundary and binds retries to the immutable request content. The web proxy permits only those two method/path combinations. Schemas were installed through independent proposal `21382227-c9fa-49de-b7df-5772b7220054`: new AccountDimensionPolicy and two additive legacy-optional JournalLine fields.

Validation and runtime evidence are recorded in `evidence/nin17-account-dimension-policy.json`. These checks do not establish authentic source journal publication, accounting completeness, ERP posting, financial close, full Finance application acceptance or product release acceptance.
