# Calculated display values in reviewed object bindings

The initial contract consumes a successful shared Function's exact, top-level text property as an ObjectBinding display value. The existing durable ontology operation prepares a canonical ResourceProposal; independent review remains the publication boundary. It does not directly publish an object from a calculation.

The authentic case uses CompanyDimension `7959af7f-a1bb-5573-8006-d1fc14f58681`, whose retained source header is `Region` and source column is `Y`. Its canonical `dimension_id` references existing DimensionDefinition `e241052e-4f47-56b6-b1ea-fab72d17f0a7`. The reviewed calculation yields `Region · source column Y`. A `CANONICAL_REFERENCE` binding follows `dimension_id` and uses this exact calculated text as the proposed display name. An empty field mapping preserves every existing target attribute. The CompanyDimension observation and source evidence remain unchanged.

The operation receives the exact successful invocation reference and its complete query page. The configured display property must be a declared top-level output, with matching canonical property and source-object versions. Missing or incompatible retained values cannot silently fall back to recomputation. Existing target-version checks and the shared review process govern publication.

The shared BindingDefinition also permits compatible text or decimal derived properties in target-field mappings. Stored and calculated inputs are explicit alternatives, with no calculated identity. Nonempty mappings still supply every required target field. Empty mappings are limited to an existing canonical reference and preserve all target attributes. Legacy stored-field requests serialize unchanged.

Proposal preparation and independent review reload the exact scoped Function receipt, verify the original object bytes and complete declared property matrix, and reconstruct the proposed values. Function, binding, property, schema, source and target heads remain fenced; the proposal must cover its entire retained source set. SQL migration 056 separately enforces receipt, scope, query, original source, property and mapped-value equality at publication. Verified historical calculation dependencies remain in impact/security traversal without creating false live feedback cycles; actual FIELD cycles remain blocked. Readiness now requires migration 56.

## Verification sequence

`scripts/verify-calculated-binding-runtime.py` separates normal definition review (`--prepare`), Function execution (`--calculate`), pending operation creation (`--proposal`), adoption of a browser-created operation (`--operation-id`), and explicit independent approval (`--approve`). The master operator must inspect the pending browser proposal before authorizing approval. `--replay` reads the retained operation and invocation without generating a new proposal.

The proof checks that the pending mutation identifies the same canonical target, preserves target attributes, retains the expected previous version and leaves the source untouched. After independent review it checks the new display version and exact source, Function and property pins in its trace. A browser-created operation can be inspected without creating a duplicate operation.
